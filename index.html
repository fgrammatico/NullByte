Design Document v1.0

NULLBYTE

A hacker-themed Minecraft Bedrock Edition adventure where players progress by solving cybersecurity puzzles, exploiting simulated vulnerabilities, and racing to achieve root access before the system's defenses shut them out.

01

Addon Architecture

Core Systems

All core logic is implemented using Minecraft Bedrock Addons (Behavior Packs and Resource Packs). Custom scripts are not supported on Realms. The adventure is designed using in-game mechanics, tagged blocks, and creative use of Bedrock's UI and triggers.

Multiplayer Support
All progression, noise, and permissions are tracked per player using Addon mechanics. Multiple players can be at different stages simultaneously.
Installing Addons
Local: Download the .mcpack or .mcaddon file, open Minecraft Bedrock, and import via "Settings" → "Storage" → "Import". Apply the pack to your world.
Realms: Create or edit a Realm, go to "Add-Ons" → "Behavior Packs" or "Resource Packs", upload and activate your pack.
Note: Realms do not support custom scripts or server-side code. Only Addons (packs) are allowed.

Defense Counter-Play
Exploits can be auto-patched by the defense system when noise reaches ALERT (50+). If you exploit the firewall and then trigger ALERT, the IR team patches it — your exploit becomes useless. Players must manage noise carefully or use stealth commands to stay below thresholds.
03

Permission Escalation Tree

4 Levels

Permissions are escalated through specific commands, each requiring a puzzle reward as a prerequisite. Permissions can be revoked by the defense system during breach or lockdown events — players may need to re-earn credentials.

GUEST

Guest — Anonymous Session

Starting permission. Can run recon commands (scan, ls, cat, whoami, help). Cannot access restricted areas or run exploit commands.

→ Unlocks: scan, ls, cat, whoami, help, login (when credential found)
USER

User — Authenticated Local User

Gained via login command after finding the credential chest. Unlocks exploit commands and stealth operations. Can attempt firewall bypass.

→ Unlocks: exploit firewall, exploit ids, patch covers, sudo
ADMIN

Admin — Privileged User

Gained via sudo after cracking the password hash in the Nether. Grants access to encryption exploits and the kill command. Required to enter the End.

→ Unlocks: exploit encryption, kill patrol, exploit root (when armed)
ROOT

Root — Full System Access

The win condition. Gained only by executing exploit root in the System Core with the root exploit armed. Ends the game: defenses stop, system shuts down.

→ Game Over (Victory): all defenses disabled, victory sequence plays

Noise & Detection Model

Stealth Mechanics

Noise is the game's stealth system. It ranges from 0 (completely silent) to 100 (full system lockdown). Noise accumulates from player actions and decays passively over time. Crossing thresholds triggers escalating defense responses.

06

Full Exploit Chain

Complete Playthrough Path

This is one complete path from guest to root. Players may discover steps in different orders or take alternate routes (e.g., disabling IDS before exploiting the firewall for less noise penalty).

1

Reconnaissance

Run scan, ls, cat /var/log/auth.log, and cat /etc/config to enumerate the system. Learn about the firewall, IDS, encryption, and hints about where credentials are stored. Noise cost: ~5 total.

2

Credential Harvesting

Navigate the Overworld to find the credential chest (tagged nullbyte:credential_chest). Opening it sets the hasCredential flag. Also locate the IDS bypass chest and the log analysis sign to collect the exploit token and IDS bypass module. Noise cost: 0 (puzzle completion rewards −3 noise each).

3

Authentication — login

With the credential flag set, run login. Permission escalates from guest → user. The login command becomes available and auto-succeeds because the precondition is met. Noise: +3. Total: ~8.

4

Disable IDS (Optional but Recommended) — exploit ids

If the player collected the IDS bypass module, they can run exploit ids before exploiting the firewall. This doubles the passive noise decay rate, giving much more breathing room. Smart players do this first. Noise: +12. Total: ~20.

5

Firewall Bypass — exploit firewall

With the exploit token and firewall not yet patched, run exploit firewall. This sets the firewallBypassed flag and unlocks the Nether area. Warning: if noise reaches 50+ while the firewall is bypassed, the defense system auto-patches it. Noise: +15. Total: ~35.

6

Navigate to Nether — Restricted Services

With the Nether unlocked, travel through the Nether portal. Find the sudo puzzle (a redstone circuit representing a password hash cracking challenge) and the compromised server NPC. Solve the redstone puzzle to earn the sudo password. Noise: 0 from puzzles.

7

Privilege Escalation — sudo

Back at a terminal, run sudo. With the sudo password flag set, permission escalates from user → admin. This unlocks exploit encryption, kill patrol, and the path to the End. Noise: +8. Total: ~43.

8

Lateral Movement & End Access

Interact with the compromised server NPC (requires hasSudoPassword flag) to complete lateral movement. Navigate to the End portal. Find the encryption key chest in the System Core. Noise: 0 from puzzles.

9

Break Encryption — exploit encryption

With the encryption key found, run exploit encryption. This breaks the core encryption and arms the root exploit (sets rootExploitReady). Noise: +20. Total: ~63. Use patch covers here if noise is getting high.

10

⭐ Execute Root Exploit — exploit root

From within the End dimension, with the root exploit armed, execute exploit root. Permission escalates to root. The system shuts down. All defenses stop. Victory. Noise: +50 — but it doesn't matter. Game over (win).

Puzzles by Biome

8 Puzzles Across 3 Areas

Each area contains puzzles that teach a specific cybersecurity concept. Puzzles are detected via tagged blocks and grant flags that unlock progression. The map should be designed so players naturally discover puzzles through exploration.

🌿

Overworld

USER SPACE
1
Credential Chest

Find and open the backup storage chest containing default system credentials. Located in a "server room" build.

→ Grants: hasCredential (unlocks login)
Concept: Credential Harvesting / Default Passwords
2
Log Analysis Sign

Read a sign in the "security office" area that reveals where exploit source code was hidden by a rogue developer. Requires credentials first (simulates needing access to read logs).

→ Grants: hasExploitToken (unlocks exploit firewall)
Concept: Log Analysis / Insider Threat
3
IDS Bypass Chest

A hardware lab contains a locked cabinet with an IDS bypass chip left by a compromised developer. Players who find this can disable the Intrusion Detection System.

→ Grants: hasIDSBypass (unlocks exploit ids)
Concept: Supply Chain Attack / Insider Threat
🔥

Nether

RESTRICTED SERVICES
4
Password Hash Crack

A redstone puzzle representing a password cracking challenge. Players must activate the correct sequence of levers (representing hash iterations) to "crack" the admin password. Located near a compromised admin workstation build.

→ Grants: hasSudoPassword (unlocks sudo)
Concept: Password Cracking / Hash Analysis
5
Compromised Server

An NPC representing a compromised internal server. Players with admin credentials can interact with it to complete "lateral movement" — pivoting from one compromised machine to the next.

→ Grants: hasServerAccess (unlocks End area)
Concept: Lateral Movement / Pivoting
💜

The End

SYSTEM CORE
6
Encryption Key Vault

A "cold storage" chest in an isolated area of the End. Contains the encryption key needed to break the core encryption layer. The vault is physically separated from the main area to encourage careful navigation.

→ Grants: encryptionKeyFound (unlocks exploit encryption)
Concept: Key Management / Cold Storage
7
Master Control Panel

A redstone activation target representing the final system lock. Players must activate it after breaking encryption to gain full access to the system core terminal.

→ Grants: coreAccessGranted (enables final terminal)
Concept: Physical Access / Root Access
Map Design Suggestions
Each area should have a distinct visual identity reinforcing its role: the Overworld should feel like a corporate office/server room, the Nether like a hot datacenter with visible infrastructure, and the End like an isolated cold vault. Terminal blocks (tagged nullbyte:terminal) should be placed at key waypoints. Defense mob spawn points should be tagged in the map so the script can summon near them rather than using random offsets. Signs and chest placements correspond to the trigger tags defined in PuzzleManager.
